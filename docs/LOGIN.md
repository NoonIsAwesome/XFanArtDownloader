# 登入與儲存登入狀態

1. 開啟桌面 App，按「開啟瀏覽器登入」。
2. 在彈出的普通 Chrome／Edge **專用視窗**內登入 X。使用 Google 帳號時，使用網站的 Google 登入流程；不要將密碼貼到 App 或 Issue。
3. 確認已進入 X 登入後畫面，再**關閉剛才的專用瀏覽器視窗**。日常使用的其他 Chrome 視窗不用關。
4. 回 App 按「儲存登入狀態」。程式會短暫在背景擷取該專用設定檔的 X Cookie，保存後自動關閉背景程序。
5. 選擇標籤及來源，開始收集。

關閉 App 不會強制關閉你正在操作的登入視窗，也不會強制顯示作者資訊。作者資訊可從頂端按鈕自行開啟。

## 為何要先關閉專用視窗

舊版在人工登入期間啟用遠端除錯；Google 可能拒絕由自動化軟體控制的瀏覽器。新版將人工登入和背景儲存分開，登入階段沒有遠端除錯參數。[Google 說明](https://support.google.com/accounts/answer/7675428)

Chrome 設定檔同一時間應由同一瀏覽器程序使用。App 不強制結束人工登入程序；若該設定檔仍被占用，會提示關閉後再試，不會轉而接管日常 Chrome。

## 常見狀況

- **提示關閉專用視窗**：關閉剛才登入用的所有專用視窗，等幾秒再儲存。不要刪除 lockfile、DevToolsActivePort 或設定檔來強行解鎖。
- **缺少登入 Cookie**：在專用視窗確認登入的是 X；只有 Google 登入完成、尚未回到 X，仍不算 X 登入完成。重新開啟、完成 X 流程、關閉後再儲存。
- **Google 額外要求驗證**：照網站正常操作。移除登入階段的除錯方式不能保證 Google 對所有帳號與環境都不提出安全驗證。
- **重開 App 後想儲存**：保留既有專用設定檔，且該視窗已關閉時，可直接按儲存，不必為此再開一個登入視窗。
- **已有 Cookie 檔**：以獨立的「匯入 Cookie 檔」選擇 Netscape TXT 或舊 JSON 清單。這是選用方式，儲存失敗不會自動跳出選檔視窗。
- **檔案已保存但下載仍要求登入**：本機驗證只確認 Cookie 格式、必要組合與已知期限，X 仍可能使登入失效。重新登入後再儲存。

## 請勿分享

`data/cookies.txt`、`data/browser-profile/`、下載歷史資料庫與包含貼文／檔案路徑的紀錄都可能含個人資訊。不要上傳到 GitHub、貼進 Issue 或附在一般錯誤回報中。登入流程與資訊使用邊界見 [SECURITY.md](../SECURITY.md)。

## 選用命令列入口

`tools/save_cookies.py` 使用相同的專用登入流程。在專案根目錄完成 `setup.cmd` 後執行：

```powershell
.\.venv\Scripts\python.exe tools/save_cookies.py
```

已有關閉的專用設定檔時，可加上 `--save-existing` 直接儲存。桌面登入控制程式位於 `desktop/login_browser.py`；命令列工具和 App 共用根目錄的本機 `data`。
